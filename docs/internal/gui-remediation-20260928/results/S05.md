# S05 結果: BGC の直接 RBH と生物学的な表示名（G06・G10）

作業ブランチ: fix/gui-feedback-remediation-20260928（S04 commit 2e0fdfba の上）。
Product 契約・保存 schema・rationale enum・ambiguity policy は変更しない。既存の一意 RBH 契約（`unique_direct_rbh`）を Web で実現した。

## 1. 原因（S00 第 7 節の確認と追加の発見）

1. Web の helper request の `directEdges` は `group.orthologEdges` から作られていたが、feature catalog は edge を数だけに縮約する（S00）。常に空で、livA 基準の record-5 は racL/racM の曖昧として Review になっていた。
2. 追加の発見（PR #641 由来）: #641 の `projectGeneratedProteinRecipe`（3f74d507）は、Web LOSATP の Generate 後に確定する request から computed typed result（`orthogroupResult` / `collinearityResult`）を外し、recipe（`generatedProteinComparison` mode `orthogroup`）だけを残していた。
   - この request を Worker で decode・plan すると、Python planner が protein BLASTP を再実行しようとし、browser では「LOSAT または BLAST+ が無い」ValidationError になる。
   - 結果として、新規 LOSATP Generate 直後の Align（S03 候補でも再現）と record rotation（S04 で記録した既存失敗 linear-multi-record:3792）が失敗していた。dev 57cef3ba では通る。
   - 原因は Worker 内 Python の例外文を一時的に取り出して特定した（計測用の変更は SHA-256 一致で復元済み）。

#641 との食い違いの判断（Owner-delegated、ユーザー指示「こちらのセッションの仕様がより合理的であれば優先」）:
- #641 は「導出グラフを二重に保存しない」ために確定 request から typed result を外した。Product Contract に対応する決定は無く、根拠はコード comment と unit test 1 件だけ。
- S05 の仕様は「Worker が準備する canonical resource から edge を取得する」。確定 request が自己完結しないと、Align・record rotation・Save→Load 後の Align が BLASTP を必要とし、browser では失敗する。
- 保存 Session は再び typed result を含む（BGC で 344 KB）。これは dev 57cef3ba と Gallery の形と同じで、新しい形式ではない。#641 の recipe-only 形式は dev/main に入っていない branch-only の中間形式なので、reader や migration は追加しない（CLAUDE.md の persisted-format 規則）。

## 4. browser の結果

最終コードで 5 flow を 1 回ずつ実行した。page error・unhandled rejection は全 flow で 0。JSON の SHA-256 先頭: load-align 65e7aaed、review-right 0ed80a9a、generate-align 5b9abf3f、para 79ba323f、fresh-losatp 1d187749。

| flow / 段階 | Review | record-5 | 方向（record-1） | Worker（diagram） | LOSAT Worker |
| --- | --- | --- | --- | --- | --- |
| load-align: Gallery Load | — | 保存 plan（livE 基準） | forward | 構築なし | 0 |
| load-align: livA Align… | 開かない | racM `unique_direct_rbh` | 保持 | resolve 1・run 1 | 0 |
| load-align: livE Align…（Keep） | 開かない | rbmC | 保持（新規反転なし） | resolve 1・run 1 | 0 |
| load-align: Save → fresh Load | — | 保存 plan を復元 | 保持 | 送信なし | 0 |
| review-right: livA Review → All right | 明示で開く。racL=coortholog、racM=rbh を表示し racM を選択済み | racM（Apply 後 `user_selected`） | 新規反転（明示） | resolve 2・run 1 | 0 |
| review-right: livE Align…（Keep） | 開かない | rbmC | 反転を保持（新規反転なし） | resolve 1・run 1 | 0 |
| generate-align: Gallery Load → Generate → livA Align… | 開かない | racM `unique_direct_rbh` | 保持 | Align で resolve 1・run 1 | 0 |
| para: parA Align… | 開かない | racL `unique_direct_rbh` | 保持 | resolve 1・run 1 | 0 |
| fresh-losatp: 5 GenBank → LOSATP Generate → livA Align… | 開かない | racM `unique_direct_rbh` | 保持 | Align で resolve 1・run 1 | Generate で 4、Align で増加なし |

- fresh-losatp は Session を使わない新規 Linear 入力で、Generate が実際に LOSATP を走らせる。これで、Session の resource だけから edge を読む実装を検出できる。保存した Session は `orthogroupResult`（344,284 bytes）と `generatedProteinComparison` mode `none` を持つ（Gallery と同じ形）。
- 名前: 全 flow・全段階で、Review 本文と inspector の本文に record key（`record-N`）、feature hash、`Internal ID`/`Feature ID`/`Record ID` が出ない。例: 「Streptomyces lividus CBS 844.73 · BGC0000708 | livA · CAG38712.1」「Streptomyces fradiae MCIMB 8233 · BGC0000711 | hypothetical protein · CAH58702.1」「Streptomyces ribosidificus ATCC 21294 · BGC0000713 | racM · CAG34707.1 | Unique direct RBH」。Save → fresh Load 後も同じ。
- Keep の自発反転は無い。review-right の record-1 の反転は明示した All right の結果で、続く livE の Keep はそれを保持しただけ（S00 の G07 の結論と一致）。
- 環境上の逸脱: fresh-losatp では LOSAT の実行方式を serial にした。配信した `http.server` は cross-origin isolated でなく、threaded のままでは Generate が LOSAT Worker を作る前に UNKNOWN で失敗する（dev 57cef3ba でも同じ。既存 browser spec も serial を使う）。
- 途中の試行（Gallery の LOSAT cache を消して Generate: imported comparison を再利用し LOSATP は走らない、threaded のまま dev・S03 で fresh 入力）は `$S00_BASELINE_DIR/evidence/s05-bgc-attempts/` に移した。
