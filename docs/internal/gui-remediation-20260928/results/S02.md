## 1. 実装

`tools/check-web-change-budget.mjs` に一つの条件 `staticProductContractCoChange` を加え、2 か所で使った。

```text
staticProductContractCoChange =
  changed.get(productContractAuthorityPath) === 'M'     // 既存 file の in-place 変更
  AND companion paths exist
  AND changedGuards == [productContractAuthorityPath]
  AND changedAuthorities == [productContractAuthorityPath]
  AND changedCheckerImplementations == []
```

- Contract companion の拒否（`candidateAuthorityCompanionPaths`）と、runtime＋guard の blocking は、同じ条件で解除する。
- 成立時は、Review 理由「static Product Contract co-change requires human review that each changed record serializes the explicit Product Decision Owner receipt …; the Gate does not verify Contract prose」を必ず加える。
- report に `Static Product Contract:` 行（unchanged / co-change / isolated / INVALID companion）を加えた。
- 候補 map・decision が inert data であることと、Contract が機械 authority にならないことを区別して表示する。DURABLE_AUTHORITY_REQUIRED の route 説明にも co-change を追記した。
- 変更しなかったもの:
  - checker×authority の拒否。
  - narrow authority bundle の隔離。
  - mapped contract の sole-proof 判定。
  - trusted-base 実行。
  - Markdown の意味 parser（追加していない）。

## 5. 機械 Gate と人間 Review の役割

- 機械 Gate が判定するのは次の 3 点だけ。
  - path の分類（exact path、in-place、唯一の guard/authority、checker 非変更）。
  - base authority による mapped concern の評価。
  - mapped contract の sole-proof 禁止。
- 次の 3 点は人間 Review の責務で、checker は検証済みと報告しない。
  - Contract prose が explicit receipt を正しく serialize していること。
  - runtime が receipt の結果だけを実現していること。
  - 欠落欄が推測で埋められていないこと。
- この fixture は新 checker 自身の unit 検証である。実 PR への適用は、S02 が dev に入り、trusted-base workflow が base 側でこの checker を実行する時点から。
