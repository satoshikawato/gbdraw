## 2. 定義した同時更新ルール（S01 プロンプト 1〜6 との対応）

1. **対象**: `docs/internal/OPTION_INTEGRITY_PRODUCT_CONTRACT.md` の in-place 変更と、その結果を実現する runtime・tests・docs。Contract の追加・削除・rename・copy と、類似名の path は対象外。
2. **Review と receipt**: 常に Review REQUIRED。変更した各 record に Product Decision Owner の explicit receipt（choice、rationale、preservation、retirement scope、accepted residual risk、owner、date）を serialize する。欠落欄は推測で埋めず、未解決とする。
3. **除外**: checker 実装、detector、evaluator、workflow、map、durable decisions、architecture rules、accepted violations、`tools/web-change-policy.json`、規範文書、PR template、guard test。Contract が唯一の guard/authority 変更でなければならない。
4. **自動昇格の禁止**: candidate Contract は machine authority にならない。machine Gate は path を分類し、mapped concern を base authority だけで評価する。parser が読まない Product 意味を Gate が検証したとは報告しない。
5. **既存経路の維持**: mapped behavior contract を候補変更だけで hard 証拠にする禁止は維持。Contract-only、runtime-only、mapped decision の経路も維持。
6. **移行条項**: この経路は PR の base checker が実装したときにだけ有効。有効化前は現行の全 companion 拒否が続く。有効化後に置き換えるのは、Contract lifecycle と各 record にある「authority を dependent runtime より先に merge する」手続き要件だけ。Product 結果・保持条件・互換性は変えない。Contract 側の古い手続き文は、最初に許可された co-change（S03）で整合させる。

新しい署名基盤、承認 UI、JSON registry、Markdown 意味 parser は追加していない。
