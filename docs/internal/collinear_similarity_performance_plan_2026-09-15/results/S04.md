## Owners, snapshots and removed work

- `_index_core_support_evidence` scans `best_by_direction` once and appends each
  directed row to the unassigned endpoint's bucket for the assigned endpoint's
  group. Incoming-only and outgoing-only rows participate equally. Reciprocal
  rows remain distinct evidence; a self row never crosses assigned/unassigned
  membership. Group membership is unique at this inference boundary.
- `core_member_snapshot` now holds those evidence buckets, frozen before the
  assignment loop. No bucket aliases `group_by_protein` or the member sets.
  `_best_evidence_between_protein_and_members` visits each connected row once,
  reducing same/cross support and diagnostics together. Positive normalized
  scores, membership coverage/domain rules and `_anchor_core_hit_rank` remain
  the owners of ranking. The candidate's support formula, evidence priority,
  high/low decisions, gap ratios and related-edge handling are unchanged.
- The first index is deleted after assignment. After record-local edges and
  components are selected, a second index uses expanded cross-record membership
  if there are components to screen. Every component is screened before local
  group insertion. This index is then deleted before `_append_record_local_orthogroups`.
  Later related-edge selection uses the live updated group map as before.
- Protein-to-member lookup already exists as `member_by_protein_id`. Collinear
  anchor metadata now reads each endpoint once, sharing group resolution with
  representative metadata. The old `_orthogroup_id_for_edge` repeated lookup is
  removed. `_edge_metadata_for_protein_pair` owns edge metadata for both genomic
  links and Collinear anchors; the duplicate Collinear edge scan is removed.
- `_index_orthogroup_edges` extends an undirected endpoint map in membership-edge
  then related-edge order. Each touched group holds an endpoint map and an
  integer offset into those existing sequences. A lookup advances only until
  the requested endpoint is found; earlier endpoints are reused and every edge
  is visited at most once per conversion call. No per-group iterator or combined
  edge-list copy is retained. `setdefault` preserves the first matching edge and its
  original fields/direction. An unknown endpoint advances the offset to the end.
  The direct two-ID comparison avoids temporary sort lists. Member counts
  use `_orthogroup_member_counts`; repeated per-row sums are removed. Genomic
  conversion builds counts lazily for touched groups; Collinear retains its
  existing all-group count preparation and combines text-coerced group keys.
- `_index_rbh_groups` replaces group-times-RBH-set reconstruction with
  protein-to-RBH ordinals. Per-group ordinal union and sort preserve original
  RBH mapping order, multiple groups, duplicate proteins, and distinct raw keys
  whose text IDs coincide. Members, names/descriptions, paths and edge sequences
  retain their existing serialization owners.
- Collinear requests `comparison_pairs=()` from the existing selector. That
  argument only controls display projection: normalized evidence, inference,
  `all_edges_by_pair`, groups and exhaustive paths are still produced. Its
  consumer uses those fields and builds anchors for its own validated pair list.
  No new skip flag or inference path exists. The display helper still prepares
  secondary-edge groups once even when the pair loop is empty; this residual
  work is not described as eliminated.

All indexes are private call-local containers. Support and RBH indexes are
populated once, then read within their stage. Endpoint maps are populated
progressively from the stored offset during the synchronous projection call. Rows and members are frozen dataclasses or normalized
row tuples; the surrounding result dicts, member lists and DataFrames remain
mutable. No index is stored on a result, in a cache, or across public conversion calls.
The source result remains stable during each synchronous conversion.
S05 must not cache these local indexes, or infer
immutability of result containers.

Removed costs: U×G candidate attempts, two full member scans per attempt and
per-attempt member sorting, repeated group edge materialization, and repeated
RBH-member set construction. Index construction remains O(E) expected dictionary
work per membership snapshot; reduction depends on connected evidence, followed
by candidate sorting. Dense evidence retains dense work and index storage.
Protein/edge sorting, representative/name construction, display work, cluster
merging and exhaustive path enumeration remain. The selector is not strict O(E).
R>=24 legacy path enumeration is outside this measurement scope.
