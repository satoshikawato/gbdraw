## Processing order and retained responsibilities

1. Search parsing and `filter_protein_hits_by_thresholds` own numeric coercion
   and raw threshold filtering. Direct selector callers supply directional hit
   tables; the selector does not silently reapply search/display thresholds.
2. `select_rbh_orthogroup_edges_from_directional_hits` calls
   `_select_member_candidate_hits_per_query`. Finite limits use numeric
   coercion, stable best-hit sorting and distinct-pair selection, then retain
   **all original HSP rows** for those pairs. Unbounded limits validate columns
   and copy/reset without an early numeric conversion.
3. `_normalize_directional_hit_table` validates columns and coerces numerics
   again before the shared aggregation owner. `_coerce_outfmt6_numeric_columns`
   rejects nonnumeric/NaN/infinite numeric fields with the existing ParseError.
4. Aggregation drops missing/unknown IDs and nonpositive protein lengths,
   retains the existing representative rank, interval clamp/union and integer
   length totals. Original position resolves complete ties; pair appearance
   determines output order. The same empty-table helper owns empty columns and
   object dtypes. Input frames are not mutated.
5. The existing normalization owner applies coverage filtering **after** union
   and **before** `_fit_expected_bitscore_model`. The inference caller still
   explicitly uses `min_coverage=0.0`; the private normalizer's default and
   domain-only classification remain unchanged. Fit/fallback selection,
   directional dedup, membership, edges/paths and projection are unchanged.
6. Collinear ON reaches that selector. OFF retains its existing member-filter
   plus direct anchor/block construction. Scope filtering retains the existing
   self/directional evidence semantics. No new display suppression is added.

`_HspPairAccumulator` is call-local private storage under the same owner. It
retains one representative tuple and rank, lengths/count/total, and two interval
lists per valid pair. It never holds a list of every HSP tuple. Unknown/nonpositive-length proteins have no accumulator. A single table-wide
`groupby(sort=False, observed=True).size()` preserves pandas ID coercion and
counts without making pair DataFrames; unobserved categorical pairs contribute
no rows, as in the old loop. This is one Python HSP row iterator, not a claim
that pandas performs only one physical memory pass. Rank errors from direct
private calls are emitted in pair order. Accumulators are released before
constructing the output DataFrame. Interval sort remains in `_covered_length` / `_merge_coverage_intervals`, so the target
is `O(H + Σ h_p log h_p)`, not strict O(H). The new scan can accumulate intervals
before discovering a pair's nonpositive representative; public thresholded
workloads and private rejected-input correctness are verified separately.

The test oracle freezes only the removed loop from `9a4f7e29`, reusing unchanged
rank/interval helpers. It protects private observations without declaring them
new public authority. The public numeric rejection boundary is tested separately.
