## Current behavior and non-waivable constraints

Current all-path arrays are public and saved. Catalog/popup needs a count but
the arrays have already expanded at inference and typed encoding. Some native
derived metadata serializes them again. No existing UI browses all paths, but
that is not permission to retire external Python/typed access.

- Architecture: one inference owner and one canonical render path. Any new
  persisted compatibility burden gets its required full exception evidence and
  separate maintainer review; this Product choice does not waive that review.
- Security/privacy: local data/Worker operation, same validation and SVG
  sanitization, no dependency or upload/service addition.
- Scientific correctness: preserve all retained evidence/members and the entire
  ordered deduplicated path language, first-edge IDs and shared information.
- Compatibility: read supported real published formats; preserve arbitrary
  supplied legacy path corpus, not its inferred edge closure. No branch-only
  readers. Candidate authority cannot authorize candidate runtime.
- Resource safety: do not run huge legacy enumeration to prove a formula;
  no hidden cap or approximation. Explicit complete output costs Ω(L).
- Evidence: S02 proves canonical DAG metadata equivalence and big-integer
  transfer. S06 must still validate actual new writer/reader/Worker/browser
  lifecycle, memory and timing on its implementation head.

## Choice PATH-B — lossless-graph

- **Complete outcome:** normal producer/render/save uses the lossless ordered
  DAG representation. Retain exact count, old-ranked individual paths, all
  first-edge IDs and shared tuples. Explicit all-path retrieval and
  `path_representation='exhaustive'` return the old dataclass/tuple contract.
  Existing precomputed tuples and published path arrays read into an explicit
  legacy corpus without inference or data loss. Details/types/errors are fixed
  in [S02_PATH_CONTRACT.md](S02_PATH_CONTRACT.md).
- Preserved effects: complete scientific information and existing figure/UI,
  supported input replay, member edits/downloads, identity/provenance, raw reuse,
  last-success Result and transactional recovery.
- Added effects: exact count and rank/specific-path access without all-path
  allocation; exact decimal-string transfer beyond JS safe integers; ordinary
  path storage proportional to the graph rather than its path expansion.
- Lost effects: default producer return is no longer the old tuple-valued
  `OrthogroupResult`; new saved typed/derived payloads no longer always contain
  `orthologPaths` arrays. Those forms remain explicitly obtainable, subject to
  output cost. Old binaries reject new graph Sessions/resources.
- Retired effects **proposed, not accepted**: implicit all-path allocation and
  all-path arrays as the default public/persisted representation; reliance on the
  old default requires migration to the explicit exhaustive keyword/conversion.
- Discoverability/accessibility: document new public access and exhaustive
  continuation in the existing API reference; GUI controls/popups stay as today,
  count text remains exact. No new paging/search/export UI.
- Canonical state update: one compact result at existing success publication;
  no separate graph/array authorities for a newly inferred group.
- Undo/Redo: same artifact owner and mutable intent; compact data travels through
  retained snapshots and any existing clone boundaries.
- Session/regeneration: normal new data compact; old explicit corpus preserved
  when read/saved, so its already-present Ω(L) data does not magically shrink.
- Export/artifact: geometry and edge IDs unchanged; catalog/interactive counts
  can remain schema 3 with decimal text. Typed/derived/Session writers advance;
  request/raw/manifest/bindings grammars remain as documented in the design.
- Validation/error: new DAG input gets structural/count/identity checks and
  explicit cycle rejection; no silent exhaustive fallback. Existing supplied
  cyclic/partial/noncanonical-ID legacy tuple corpus remains readable. Integer,
  ID and out-of-range retrieval errors are specified in the design. Existing
  public exhaustive input behavior must be preserved, including validation
  boundaries; uncovered canonical-input assumptions stop S06 implementation.
- Failure/recovery: generated-cycle/inconsistent-graph failure publishes no
  partial result; previous Result and eligible raw retry remain. Explicit
  exhaustive failure does not mutate the committed graph or active Session.
- Scientific output: exact ordered information preserved, without new biological
  interpretation. Path IDs still reflect result order, not global identities.
- Cache/provenance: raw identity unchanged; derived identity adds representation/
  ordering version. Update S05's existing owner, not another finished-payload cache.
- Performance: O(V+E) graph entries plus sorting/big-integer costs for canonical
  inferred DAGs; explicit all-output Ω(L); old explicit input still costs its
  size. No S02 full-Generate/browser speedup is claimed.
- Compatibility: **3 new persisted source-form obligations** planned (typed 2,
  derived 3, Session 42), plus explicit Python continuation; no catalog 2,
  typed branch-only or intermediate Session migration. Exact architecture CB
  sets/counts depend on S06 implementation and require separate review.
- Architecture: one graph/access owner and one shared legacy corpus adapter;
  remove eager normal paths. Do not retain the old inference as a runtime fallback.
- Evidence: 1,024 exhaustive small DAG topologies, seeded duplicate/reverse cases,
  all metadata equivalence, old R=8/12/16 oracles, compact R≥24 counts/ranks/shared,
  real catalog/popup decimal transport and permissive legacy typed fixture.
- Missing implementation evidence: new-format Python/JS round trips, offline
  browser lifecycle, new Writer rollback/admission, performance and memory on S06.
  These are start/acceptance gates, not work claimed complete by a prototype.
- Residual risk **for the human to accept or reject**: integrations using the old
  default/array fields need migration; old readers reject new files; explicit
  huge exports may exceed resources; future inference must re-prove the DAG and

- Route: **DURABLE_AUTHORITY_REQUIRED**, followed by any required separate

## Evidence-first work completed and limits

Deterministic evidence answers whether canonical inference is acyclic despite
reverse/same-record evidence and whether a compact index can reproduce the
**whole** current metadata contract. It does. The test-only prototype is not a
production reader/writer or browser integration. It intentionally refuses
cycles; old public explicit data is characterized separately.

The graph-only report computes R=24/32/56 and R=56 plus a disconnected edge
without invoking the old enumerator. S01 R=8/12/16 full oracles remain equal.
No large legacy expansion, production optimization, new schema constant,
authority change or expected SVG baseline is part of the evidence work.
Reproduction, hashes and verification logs are linked from [S02.md](S02.md).

S01 same-code timing had 24 pass / 3 regression / 15 inconclusive. Neither choice
is justified by claiming those measurements show a speedup. Future timing keeps
the same gate and needs less-contended conditions. Exact count/operation and
metadata evidence are independently valid.

## Engineering recommendation

Recommend **PATH-B / lossless-graph** because canonical normal work can preserve
the complete ordered path information without allocating every path. The
metadata oracle covers the first-edge and shared semantics that a count-only
experiment would miss. The explicit legacy corpus handles real published data
without inventing edge-closure paths.

**This recommendation is not Product authority.** Neither retirement nor
residual risk above is accepted until the human supplies it explicitly. A choice
cannot waive missing S06 tests, architecture rules or trusted-base sequencing.
