## S02 API and result contract

Use the existing `RESOLVE_SIMILARITY_ALIGNMENT` operation:

```javascript
const { result } = await runDiagramHelperOperation(resolveOperation, {
  request: helperRequest,
  projection: { canonicalRequest: materializedBeforeRequest, orientations },
  resources: committedResources
});
const resolution = validateSimilarityAlignmentResolution(result, helperRequest);
const projected = projectSimilarityAlignmentDirections({
  resolution, expectedBinding, intent, choices
});
```

`intent` is exactly `{mode:'keep'|'right'|'left'}` or
`{mode:'custom', byRecordKey:{[recordKey]:'keep'|'right'|'left'}}`.
`choices` is optional local explicit Select/Skip using the existing helper-choice
shape; only usable admitted Python candidates are selectable. Ambiguous rows
without a choice remain unchanged with `selection_required`; no recommendation
is silently applied. The exact reference cannot be replaced or skipped.

`orientations` is either null for initial counterfactual facts or the full keyed
absolute boolean vector projected for final validation. For automatic Keep,
provide the actual current absolute vector on the first batch and reuse the
resolved final facts while the binding is unchanged. Local edits invoke only the
pure resolver. At Apply, send the local choices and projected vector in the
existing one Python batch. Counterfactual source transforms support all local
choices, but geometry for a different vector remains provisional. Require
`selectionComplete` and `geometryValidated` before commit; compare final binding
and material signature with the displayed preview. Changed material output must
refresh the preview and await another Apply. A binding mismatch returns
`{status:'stale', reason:'binding_changed', binding}` with no corrections.

A projected result contains `binding`, `records`, `selectionComplete`,
`geometryValidated`, `reference`, and `signature`. Each record supplies key,
selected anchor/status, absolute before/after reverse values, before/after arrow,
exclusion, projected centers, and proposed canonical x/y. `reference` supplies
exact anchor, logical before/after x, and finite actual delta. S02 patches the
canonical orientation/translation owners, keeps the validated Python plan
orientation-independent, and commits through existing candidate execution,
Result admission/readiness, and History finalization. Do not persist the intent,
helper facts, or a second translation baseline. Reset receipt shape and lifecycle
remain S02 work, including actual direction deltas and sparse reference delta.

The helper currently obtains layout facts through the existing renderer twice;
it does not save drawings or cache them. Large-input cost and artifact/LOSAT
reuse in the controller lifecycle remain S02/S04 verification responsibilities.
Start the next session only from the completed same-named remote, recheck its
writer and all four exact current dev receipts/ancestor, and resolve affected
Issue #602 surface requirements before replacing that surface.
