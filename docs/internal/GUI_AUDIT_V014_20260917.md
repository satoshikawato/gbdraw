## 未解決の正規表現整合性（F08）

現行devのCLIでは`(?i)NADH`のTSVが成功し、SVGに赤いpathが8個できる。
GUIはJavaScriptの`RegExp`で拒否する。
さらに決定的な小規模コーパスで以下を確認した。

| 式 / 入力 | Python `re.IGNORECASE` | JavaScript `RegExp(..., 'i')` |
| --- | --- | --- |
| `(?i)NADH` / `NADH dehydrogenase` | 一致 | 構文エラー |
| `(?P<enzyme>NADH)` / 同上 | 一致 | 構文エラー |
| `NADH\Z` / `NADH` | 一致 | 不一致 |
| `\bβ` / `β-lactamase` | 一致 | 不一致 |
| `i` / `ı` | 一致 | 不一致 |
| `(?<enzyme>NADH)` / `NADH dehydrogenase` | 構文エラー | 一致 |

入口の検証を消すだけでは直らない。`feature-utils.js`の照合はライブ配色、凡例名、
適用範囲の展開、同じルールに属するfeature数にも使われる。
必要な修正範囲は、既存の単一Diagram Workerを使うPython判定と、GUIの同期的な表示・
編集の接続である。取込、手動編集、Session復元、色の範囲選択、Generate、Undo/Redoを
同じ判定結果に揃える必要がある。部分的な式の翻訳や、失敗時の文字列一致による
代用を新たに追加していない。

同じ問題はラベル変更TSVにも及ぶ。`* / CDS / product / (?i)NADH / AUDIT_MATCH`
の5列入力は、Pythonの既存ラベルルールで有効かつ一致するが、Webの取込は構文エラーで
拒否しoverrideを1件も作らない（`label-regex-results.json`, `label-regex-python.json`）。
同じ正規表現の解釈差としてF08にまとめ、別の件数には加算しない。

## PDFフォント候補の統合制約（F12）

追加候補は14ファイル、計9,085,656 bytes。
12個のLiberation TTFは既存`gbdraw/data`とバイト単位で同一。
2個のNoto Sans JP TTFは既存の同梱WOFF2（400/700）からFontToolsで変換したもの。
生成処理は既存のvendor準備ツールに置き、OFLの帰属表示を更新した。
外部CDN、Pythonのmain-thread実行、新しい実行時ライブラリは加えていない。
フォントはPDF出力時にだけ取得し、取得失敗後の再試行も検証する。

実際のPDFをPyMuPDF 1.28.2で独立に描画し、
`ゲノム β-lactamase α ≥ 95%`の表示と文字抽出を確認した。
フォントにない文字は文字化けしたPDFを保存せず、文字コードを含むエラーを返す。

ただし`docs/internal/WEB_CHANGE_POLICY.md`は
「binary runtime additions or vendored runtime changes」をハード失敗と定める。
`check-web-change-budget.mjs`の結果も、この追加を理由に**Gate FAIL**である。
Review REQUIREDとは別の条件であり、通常のレビューやarchitecture-changeラベルで
解除できない。ガード変更や例外の自己承認は行っていない。
この段落は制約の記録であり、例外承認やexact-head承認の代わりではない。
